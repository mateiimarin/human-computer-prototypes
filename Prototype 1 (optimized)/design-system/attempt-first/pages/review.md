# Review and feedback

Read `../MASTER.md` first. Reuse the same task context and semantic feedback colors.

**Student's question:** Where does my reasoning hold or fail?

## Composition

Maximum 1120 px area. Heading “Review your attempt,” with “Attempt 1 · prepared sample feedback” immediately below. Desktop: submitted snapshot on the left and linked feedback on the right. Smaller screens: snapshot summary followed by the issue list; each issue links to its relevant work step.

A snapshot must be distinguishable from the editable current attempt. Show its version and do not silently modify it. No official grade, mastery percentage, or generic “AI score.”

Use calm ochre cards for reasoning gaps. Each has a numbered step reference, concise issue, and an “Explain this gap” action. Example: “Step 2 · The induction step uses the claim at k + 1 before it has been established.” Do not include the full correction. Supported steps may receive a restrained check plus a factual note.

One selected issue expands an explanation field with a visible label: “Why does this step fail?” Submitting a nonempty explanation makes “Return to revise” available. The gate checks that an explanation exists; feedback on its meaning is simulated. Drafts survive close/back.

## Revision and completion

- Return to revise focuses the corresponding attempt step; student changes the work.
- Editor changes create a visible “Edited since review · recheck needed” state. Old feedback remains tied to its old snapshot.
- Recheck explicitly produces the next prepared outcome and snapshot identity.
- Repeated issue: link to the earlier explanation in this task; use neutral language.
- No issues: “No issues found in this sample review.” Main action becomes “Open reflection.”
- Issues remain: main action is Explain / Return to revise as appropriate. A secondary “Finish with gaps” action opens reflection with the unresolved list intact.

Preparing feedback may use a short busy state if useful for the demonstration, with honest “Preparing sample feedback…” wording. The fixture choice belongs outside the learner journey; arbitrary input must not appear analyzed.

## Check

Demonstrate incorrect attempt → explanation → revision → recheck, a repeated issue, no issues, and finish with gaps. Follow each issue to the correct step using the keyboard. Closing an issue must preserve the explanation and current work.
